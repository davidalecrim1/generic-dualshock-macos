# The fix

Technical record for the DragonRise `0079:0006` pad on macOS: what the device
sends, why the left stick moves the right stick, what does not work, and the
configuration that does.

Verified on macOS 27.2.1, Apple Silicon, with PCSX2 (x86_64 under Rosetta).

## 1. What the device actually sends

HID report descriptor, 101 bytes, read from the device:

```
05 01 09 04 A1 01 A1 02 75 08 95 05 15 00 26 FF 00 35 00 46 FF 00
09 30 09 31 09 32 09 32 09 35 81 02
75 04 95 01 25 07 46 3B 01 65 14 09 39 81 42 65 00
75 01 95 0C 25 01 45 01 05 09 19 01 29 0C 81 02
06 00 FF 75 01 95 08 25 01 45 01 09 01 81 02
C0 A1 02 75 08 95 07 46 FF 00 26 FF 00 09 02 91 02 C0 C0
```

The axis usages are `X`, `Y`, `Z`, **`Z`**, `Rz` — the fourth entry should have
been `Rx`. That duplicate is the bug, and it is stored on the device, not
generated by macOS.

Decoded input report (8 bytes):

| Byte | Declared usage | What it really carries |
|------|----------------|------------------------|
| 0 | X | left stick X |
| 1 | Y | left stick Y |
| 2 | Z | **a copy of left stick X** |
| 3 | Z (duplicate) | true right stick X |
| 4 | Rz | right stick Y |
| 5 | hat (low nibble) + buttons 1-4 (high nibble) | |
| 6 | buttons 5-12 | |
| 7 | vendor page `0xFF00`, 8 bits | unused, constant `0x40` |

Raw captures from the wire:

```
left stick left   : 00 80 00 80 80 0F 00 40   -> X=-128 and Z=-128 together
left stick right  : FF 80 FF 80 80 0F 00 40   -> X=+127 and Z=+127 together
left stick up     : 80 00 7F 80 80 0F 00 40   -> only Y moves
right stick left  : 80 80 7F 00 80 0F 00 40   -> only byte 3 moves
```

The mirror is one-directional and perfectly scaled: left X leaks into the
right-X slot, right X never leaks back. No information is lost — the genuine
right-stick X is present on byte 3.

## 2. Why it is not a hardware fault

- Two units of the same model fail identically, byte for byte.
- A short or cold joint would be bidirectional, noisy or intermittent.
- The mirror is a clean copy of one value into two fields, and the descriptor
  contains a typo (`09 32 09 32`). Both are firmware artifacts.

## 3. Why a plain macOS-level fix was not possible

`IOHIDUserDeviceCreateWithProperties` (republish a corrected virtual gamepad)
requires the restricted entitlement `com.apple.developer.hid.virtual.device`.
An unsigned process gets `nil`; ad-hoc signing the entitlement makes the kernel
`SIGKILL` the process. Confirmed on this machine.

Other dead ends, so nobody repeats them:

| Attempt | Result |
|---|---|
| `hidutil` | HID event-system properties and keyboard usage remapping only; no gamepad axes |
| Kext with a descriptor override | Unsupported since Big Sur; needs reduced security on Apple silicon |
| Karabiner-Elements | Virtual HID device publishes keyboard and mouse descriptors only |
| `SDL_GAMECONTROLLERCONFIG_FILE` | Ignored by SDL 3.4; only the inline `SDL_GAMECONTROLLERCONFIG` is honoured |
| PCSX2 `game_controller_db.txt` | SDL never parses it unless the app calls the loader itself |
| SDL mapping for GUID `0300457e...` | Correct, but irrelevant while the pad is claimed by the GameController framework |

Two facts that made early attempts look like failures:

1. **Apple bug in macOS 27.0–27.3**: `GCController supportsHIDDevice:` claims
   generic HID pads, SDL's IOKit backend then skips them, and SDL reports zero
   joysticks. Workaround: `SDL_JOYSTICK_MFI=0`. Fixed in macOS 27.4.
2. **PCSX2 enables both SDL backends by default** (`SDLIOKitDriver` and
   `SDLMFIDriver`), so with MFI on the pad reached SDL by a different path with
   a name-based GUID, and no mapping could match it.

The real GUID, if you need it for SDL tools, is
`0300457e790000000600000007010000`
(bus 3, CRC `0x7e45` of the raw name strings, version `0x0107`).

## 4. The fix that works

[OpenJoystickDriver](https://github.com/xsyetopz/OpenJoystickDriver) is a
notarized menu-bar app with a signed DriverKit extension. The app itself holds
`com.apple.developer.hid.virtual.device`, so it can do what an unentitled
process cannot: read the pad, decode the bytes itself, and publish a clean
virtual gamepad for every application.

Its bundled record for `0079:0006` is not sufficient — it maps **both** `Z`
usages to `RightStickX`, preserving the mirror. The working configuration
bypasses the descriptor and declares raw bit offsets.

### Record layout used

| Control | bitOffset | bitSize |
|---|---|---|
| LeftStickX | 0 | 8 |
| LeftStickY | 8 | 8 |
| *(byte 2 — intentionally unmapped)* | – | – |
| RightStickX | 24 | 8 |
| RightStickY | 32 | 8 |
| hat (EightWay) | 40 | 4 |
| North / East / South / West (Triangle, Circle, Cross, Square) | 44-47 | 1 each |
| LeftShoulder / RightShoulder (L1, R1) | 48-49 | 1 each |
| LeftTrigger / RightTrigger (L2, R2) | 50-51 | 1 each, analog 0..1 |
| Back / Start | 52-53 | 1 each |
| LeftStickClick / RightStickClick | 54-55 | 1 each |
| report length | at least 8 bytes | |

`server: OJD` is required, otherwise OJD defers to macOS, which claims the pad
through the Apple bug above and never uses it.

### Triggers must be declared as triggers, not as buttons

L2 and R2 are single bits, so the obvious move is to list them in `buttons` as
`LeftTrigger` and `RightTrigger`. That publishes a digital button, and a button
cannot move the analog trigger axis that SDL and gamepad APIs expose. The
symptom is confusing: the triggers work when OJD is not running (raw pad), and
die the moment it is.

Declare them as analog instead, with the full range of a one-bit field:

```json
"leftTrigger":  { "bitOffset": 50, "bitSize": 1, "min": 0, "max": 1 },
"rightTrigger": { "bitOffset": 51, "bitSize": 1, "min": 0, "max": 1 }
```

`ojd controller watch` then reports `leftTrigger=65535` on a full press. There is
no half-press on this hardware; the pad sends one bit per trigger.

## 5. Install

```bash
# 1. App (0.6.0-alpha.2 at the time of writing)
#    Download the DMG from the project's Releases page, drag to /Applications, launch it.
#    Grant Input Monitoring when asked.

# 2. The record
mkdir -p ~/Library/Application\ Support/OpenJoystickDriver/Controllers
cp records/0079-0006.patch.json ~/Library/Application\ Support/OpenJoystickDriver/Controllers/

# 3. CLI (optional): either use the app's menu item, or invoke the binary as `ojd`
ln -s /Applications/OpenJoystickDriver.app/Contents/MacOS/OpenJoystickDriver /usr/local/bin/ojd

ojd record validate ~/Library/Application\ Support/OpenJoystickDriver/Controllers/0079-0006.patch.json
ojd status
ojd controller show 0079:0006
```

Expected state:

```
Protocol         hid-report-layout
Ownership        physical exclusive-hid, HID input exclusive
Served by        OJD (from user)
Record           your record, .../0079-0006.patch.json
Virtual gamepad  On, publishing Generic   USB  Joystick
```

The virtual pad appears as `045E:0B0C` "Xbox Adaptive Controller" (the
SDL-compatible persona).

## 6. Verify

```bash
ojd controller watch 0079:0006 --duration 20
```

- Left stick left/right must change only `LeftStickX`.
- Right stick left/right must change only `RightStickX`.
- L2 and R2 must report `leftTrigger` / `rightTrigger` as `65535`, not as an entry in `pressed`.
- Also check System Settings → Game Controllers, and a second app (RPCS3, Steam)
  to confirm the fix is not emulator-specific.

If the triggers were bound before this record was corrected, PCSX2 keeps the old
binding and they stay dead. Right-click the L2 and R2 fields to clear them, then
bind again.

## 7. Revert / uninstall

```bash
rm ~/Library/Application\ Support/OpenJoystickDriver/Controllers/0079-0006.patch.json
# then quit the app and move it to the Trash (this also removes the login item)
```

Removing only the record returns the pad to the stock OJD behaviour, which still
mirrors the axis.

## 8. Caveats

- `0.6.0-alpha.2`, single maintainer, alpha quality. If the service misbehaves
  after sleep or replug, restart the app and read
  `~/Library/Logs/OpenJoystickDriver/OpenJoystickDriver.out.log`.
- The DriverKit extension stays "inactive" and is not needed for this pad; it is
  used for raw-USB Xbox controllers.
- Accessibility permission is not needed for this fix.
- Rumble is not wired up (the pad's 7-byte output report is unknown).
- Do not expect the physical pad to be visible to apps: it is opened exclusively
  and replaced by the virtual one.

## 9. Fallback without OpenJoystickDriver

`SDL_GAMECONTROLLERCONFIG` still corrects SDL-based apps (RPCS3, shadPS4,
RetroArch; PCSX2 only with `SDLMFIDriver = false`). See
`sdl/0079-0006.gamecontrollerdb.txt`. This path is limited to SDL software and
does not help native or Unity/Unreal games.
